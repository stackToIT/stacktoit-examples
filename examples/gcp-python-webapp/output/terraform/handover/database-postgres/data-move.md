**Step** `MAN/data/google_sql_database_instance.postgres/cleanup/logical-replication` (data cleanup, phase DECOMMISSION); owner: Data Architect.

**What.** Only after the target has run in production for the period the customer decides and the way back is no longer wanted: `DROP SUBSCRIPTION stacktoit_move;` on the target (it drops the slot on the source if the source is reachable; check `SELECT * FROM pg_replication_slots;`), `DROP PUBLICATION stacktoit_move;` and `DROP ROLE stacktoit_repl;` on the source, set `cloudsql.logical_decoding` back with a second restart if it was off before the move; remove the move host from `network.acl` of the instance and from the authorized networks of the source if it was added; delete the dump files and `restore.log`; keep a final backup of the source for the retention the customer decides before anything is deleted; replace the credentials of the target user if they were ever on a ticket or in a file.

**Why.** the move leaves a publication, a slot, a flag, an access entry and copies of the data behind; none of them stays

**Done when.** no slot, subscription, publication or dump file is left, the move host is out of every access list, the credentials are replaced

**Risks.**

**Rollback.** after the cleanup the way back is the final backup of the source; there is no other
