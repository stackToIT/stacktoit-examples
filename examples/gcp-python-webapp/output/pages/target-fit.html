How this matrix works

Every STACKIT capability is shown along independent dimensions. There is no overall verdict, no score and no yes or no: a dimension is assessed only where the capability catalogue carries a value for it with evidence, and "not assessed" means the catalogue states nothing, which is not the same as not available. A list of evidenced facts (quota limits, known issues) is counted beside its dimension and does not complete it.

The catalogue holds 321 capabilities; the Terraform facts are derived from the stackit provider schema 0.121.0. Evidence is judged as of 2026-11-07, the date of the assessment; stale evidence is no longer vouched for, which is not the same as false.

Day-2 responsibility: when a version reaches its expiry the update is performed by the provider (STACKIT). "If the Kubernetes or OS version of a cluster has reached its expiration date, SKE starts a mandatory update to the highest available patch version of the current minor version, or to the highest patch version of the consecutive minor version that is not classified as preview version." and "mandatory version updates run, even if the auto update for the Kubernetes version is deactivated". Automatic updates otherwise "only update to higher patch levels" in the cluster's maintenance window. Notice: "As a SKE user you will get informed via release notes and via email in case you are operating a cluster with a deprecated Kubernetes version." Customer: "you can check the exact expiration dates for your current Kubernetes and node pool versions in the cluster.status.expiration field via the SKE API". The page does not assign any further duty (workload readiness for the update, testing) to the customer or to STACKIT: not stated.
